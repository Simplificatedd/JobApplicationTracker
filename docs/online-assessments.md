# Online Assessments

Applications now support **Online Assessment** as a distinct status. Each application has separate Interviews and Assessments sections. Recording or submitting an assessment does not change the application status. Users can change status with the existing selector. Scheduling an interview retains the existing interview workflow.

Assessments have independent stable numbers, optional name, type, provider, link, invitation time, absolute completion deadline, time limit in minutes, optional fixed start, three-state proctoring, progress, optional submission time, result, optional score, and notes. Deadline entry reuses the existing invitation-time shortcuts (+24h, +48h, +72h, custom duration). Fixed-start and submission fields appear when relevant; results and scores can be expanded. Cards offer Open assessment, Mark submitted, Edit deadline, edit, and confirmed deletion. Archived entries remain readable.

## Storage and compatibility

- Snapshot `dataVersion` and JSON backup `schemaVersion` are now **3**.
- IndexedDB upgrades from version **6** to **7**, adding an `assessments` store with an application index. The cloud snapshot has a separate `assessments` array. No D1 table migration is needed because D1 already stores the entire snapshot as JSON.
- Startup and backup import share `migrateStageSnapshot`. Local migration writes the assessment, removes the source interview, and refreshes the application projection atomically. Cloud startup persists the normalized snapshot using the existing revision guard and retries conflicts against the newest snapshot.
- Only the literal legacy interview type `online-assessment` automatically converts. Technical, Other, take-home assignment, provider-only legacy enums (HireVue/HackerRank), provider names, and notes do not trigger conversion. Existing ambiguous types remain unchanged. Interviews have an explicit, confirmed **Convert to assessment** action.
- Converted records retain the source ID, `originalInterviewRound`, original timestamps, and a complete `legacyInterview` object, including extra historical metadata. Interview rounds are never renumbered. Independent assessment numbers follow stable historical creation/round/ID order; new or manually converted assessments use the next available number. Existing assessment numbers are preserved, including during cloud conflict rebasing.
- Valid existing links, platform, notes, invitation time, scheduled time, and resolved exact/relative deadlines map into the new fields. A legacy `true` proctoring flag maps to Yes; legacy false maps to Unknown because it was also the default, and its exact value remains in the source object. Progress/result are Unknown, and submission time/score/duration are absent. Passing a deadline never fabricates submission.
- The application `stageMigrationVersion: 1` marker disables further projection recovery and legacy deadline copying. It prevents startup/import from recreating moved or deliberately deleted records or attaching a historical assessment deadline to another interview. Projection-only old records receive deterministic IDs. Partial snapshots containing an assessment and its source interview are deduplicated only when the source matches the preserved `legacyInterview`, including custom metadata. Divergent sources produce an explicit conflict before startup/import or the mutation can persist changes; neither version is silently discarded.
- Conversion never changes current application status or rewrites existing status activities. Offer migration remains gated at **data version < 2**, independently of the current version, so modern Offered records remain Offered. Assessment actions also preserve application status, archive state, and other metadata changed concurrently in another tab.
- Provider-only legacy classifications remain provider-only through scheduling edits and normalization. Assessment edits carry field changes and apply them to the latest record during cloud revision retries. The editor compares its draft with the record captured when editing began, so unchanged fields cannot overwrite a submission/result entered elsewhere. Removed assessments reject stale updates. Conversion checks the source before removal; equivalent repeated conversions preserve newer assessment edits, while changed or deleted sources reject the conversion without saving.

## Backups and downgrade behaviour

The importer accepts backup schemas **1, 2, and 3**, validates assessment ownership, identity, numbers, enums, dates, duration, legacy source, and collection limits, then migrates the snapshot. Full export/import preserves all assessment fields and legacy source metadata. Import retains the existing replacement semantics; importing a backup repeatedly does not accumulate duplicates. Import previews count interviews and assessments separately.

Older app binaries cannot read schema-3 backups or reliably display Online Assessment. The updated server atomically rejects attempts to overwrite a newer snapshot with an older `dataVersion`, including writes from old tabs. Deploy the Functions update with the frontend. New clients also refuse unknown future data versions. Local IndexedDB downgrade is unsupported; keep a pre-upgrade backup when a rollback is needed. Assessment data is never flattened for compatibility with old binaries.

The old application CSV remains an application summary; full JSON backup is the lossless export for assessment details. Obsolete saved Online-assessment interview filters are cleared on preference normalization so moved records are not hidden by a stale filter. Users can select the new application status filter.

## Reminders and analytics

Assessment reminders use the assessment's dates and progress, independently of Interviewing status. Future deadlines and scheduled starts remain represented; overdue unfinished deadlines stay active, including unknown/expired progress. Submitted and cancelled assessments stop generating reminders. Existing archived/final-status suppression remains. The existing due-soon window and scheduled-event setting apply. Migrated reminders retain their old source IDs so dismissal state survives; the source interview is removed to prevent duplicate stage reminders. Assessment notifications have their own group and submission/date quick actions.

Interview counts and charts use remaining interviews. Assessment invitations have a separate optional chart, based on invitation time with creation-time fallback. Pipeline and application paths support Online Assessment and Assessed → Rejected. Assessment-only migrated histories are excluded from interview-specific rejection paths; actual remaining interview records take precedence. Old Interviewing activities remain intact because their original meaning cannot always be reconstructed. Calendar assessment dates are labelled **assessment events**, never fabricated completed interviews/submissions; the date uses submitted time, scheduled start, invitation time, then creation time.
